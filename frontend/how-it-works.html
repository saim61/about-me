How it works

A retrieval-augmented generation (RAG) assistant, built step by step to learn how RAG really works, and measured instead of guessed.

← Back to chat

Once, before anyone asks

  1. 1
    Write it downEverything about Saeem lives in one document, rendered to PDF, because real RAG systems start from PDFs.
  2. 2
    Extractdocling, a layout-aware model, turns the PDF back into markdown with its headings intact.
  3. 3
    ChunkOne chunk per section, so every chunk is one complete idea.
  4. 4
    EmbedA small local model (bge-small-en-v1.5, ONNX) turns each chunk into 384 numbers that capture its meaning.
  5. 5
    StoreVectors live in memory, or in Postgres with pgvector, synced by content hash so only changed sections are re-embedded.

Every time you ask

  1. 1
    GuardRate limits and cheap pre-checks handle greetings, off-limits topics, and injection attempts without spending an LLM call.
  2. 2
    RewriteGemini turns "who is he?" or a typo into a clean search query, and remembers the last few turns for follow-ups.
  3. 3
    RetrieveCosine similarity finds the 3 chunks closest in meaning. Click "How I found this" under any answer to see them.
  4. 4
    AnswerGemini answers only from those chunks, streamed word by word, and says so when it doesn't know.

Things that surprised me

  • The bigger embedding model lost. A model three times the size ranked the right chunk first far less often. Measuring beat assuming.
  • "skils" became skiing. The tokenizer split the typo into ski + ##ls, and retrieval returned the hobbies section. Rewriting the question first fixed it.
  • "And before that?" got the wrong job. The right section wasn't retrieved, so the model guessed an order. A single career-timeline section fixed every ordering question.
  • The AI judge passed a wrong answer. An LLM grading answers approved one that only sounded right. Reading answers by hand still matters.
